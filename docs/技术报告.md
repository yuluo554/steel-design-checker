# 钢结构连接与构件验算计算器 · 技术报告

> 配套仓库：`yuluo554/steel-design-checker`（Python 3.8 + 纯标准库计算内核，零 LLM、零网络）。
> 本报告写"怎么做的、为什么这样做、哪些没做到"。指标数值以 README 的指标表为唯一来源
> （那张表由 `sdc bench --all --markdown` 生成，并由测试与实跑逐行对账），本文不复述表格，
> 只在正文里引用其中已经实测的数字。

## 0. 一句话定位

把 GB 50017-2017《钢结构设计标准》、GB 55006-2021《钢结构通用规范》、JGJ 82-2011《高层建筑
钢结构技术规程》里的**连接与轴压构件验算**做成可复现的离线工具：5 个验算模块 + 设计说明文本
核查 + 107 条符合性检查单 + docx 交付物 + 桌面界面，并且**每一条结论都能回溯到"哪一条款、
哪一式、哪个表值"**——包括回溯到它为什么不出数值。

## 1. 设计立场：拒算是功能，不是缺陷

工程软件最容易糊弄人的一次输出，是"看起来算完了"。本项目的核心纪律是：

> 未与正式文本核对过的规范数值，**不许进入计算路径**；引用它的模块一律 `blocked`，
> 而且 blocked 的结果里**一个数值都没有**，只有逐项缺什么、缺在哪条渠道哪一天没核对。

这条纪律落进的是**引擎门控**（`kb/gate.py`），不是文档承诺。它有三个反直觉的推论，本报告
后面三节就是围绕它们展开的：

1. 演示一次成功计算，需要的不是代码而是**一份已核对的数据**；数据没核对完，就用
   `tests/fixtures/` 里的合成 verified 夹具跑数值通路，用真实数据跑拒算通路（§2.5）；
2. "知道条号在哪"和"一无所知"是两件事，所以 status 从二态升到**三档**（§3.1）；
3. 指标的分母可以是 0，**但 0 必须显示成"不可判"而不是达标**（§4.3）。

## 2. 主题一：条款-公式-符号表引擎与三档门控

### 2.1 数据形态

知识库分四层记录，全部 JSON 入仓，每条挂 `status` 与 `verified_by`（渠道 + 日期 + URL）：

| kind | 记录数 | verified | located | pending | 说明 |
|---|---|---|---|---|---|
| clause（条款） | 161 | 5 | 155 | 1 | GB 50017 35 / GB 55006 107 / JGJ 82 19 |
| table（数值表） | 13 | 2 | 11 | 0 | 附录 D 的 φ 表（953 格，二维）与 α 表已 verified |
| formula（公式） | 14 | 0 | 0 | 14 | 式体只写"待核对"占位，禁止按记忆补全 |
| symbol（符号） | 36 | 1 | 6 | 29 | `phi` 随附录 D 定档升 verified |
| rule（核查规则） | 10 | 0 | 10 | 0 | 依据条款全 located ⇒ 判定档位被封顶 |
| checklist（检查单） | 107 | 0 | 107 | 0 | GB 55006 全 8 章要点化 |
| case（算例真值） | 0 | — | — | — | 无来源即无真值，通过率分母为 0 |

`已挂核对档的渠道完整率 180 / 180`——任何一条 located/verified 记录缺渠道档，schema 校验
就直接失败（`tests/test_kb_schema.py`）。数据指纹 `data_fingerprint` 取 clauses+tables 的
规范化拼接 sha256，排版改动不改指纹，任一数值或条号改动必然改指纹。

### 2.2 门控：模块依赖集与反向门控

一个验算模块的依赖集 = 它引用的公式 + 符号 + 数值表 + 承载公式的条款 + **构造/限值条款**。
最后一项是 M2 补上的一个真实漏洞：构造条款（如"角焊缝最小焊脚尺寸"）不通过 `module.formulas`
进入依赖集，而是通过 `clause.formulas` **反向索引**进入（06 D18③）。不补这一条，限值检查
就可以在任何依据未核对的情况下随便编一个数。

模块状态由依赖集里**最差的那一档**决定，只要有一项不是 `verified`，结果就是 `blocked`，
并且结果对象里的数值字段全部为空——不是 0、不是 NaN、不是"仅供参考"，是没有这个字段。

### 2.3 式体是数据，不是代码

公式在库里存的是**机器可解析的 ASCII 式体**（`sigma = N / (A_n) <= f`），规范原文的记法
留在 `notes`（06 D18①）。求值器是一个白名单 AST 解释器（`engine/expr.py`）：只允许加、减、
乘、除、幂与比较、函数调用与符号名，验算式只允许 `<=` / `>=`，比值方向恒取
「作用效应 / 抗力」。这意味着：

- 引擎里**没有任何一个规范系数**——β_f、μ、P、φ、各类强度设计值全部来自数据侧；
- 这些量**禁止出现在参数卡里**（06 D18④）。用户手工传一个 φ 进来，等于绕过整套核对体系，
  引擎直接判"输入不可用"（退出码 2）而不是"算得出来"。

单位在入口层归一（力 kN/N、长度 mm/cm），式体内部只用基本单位；查表支持单数值轴 `linear`
与"分组轴 + 数值轴"两种形态（附录 D 的 φ 表就是 `section_class × λ/εk` 二维），超表界即失败，
**不外推**。

### 2.4 合成夹具：数值通路的唯一证明

真实数据一条都没核对完，可数值通路（求值、查表、插值、比值判定）必须被测试覆盖。解法不是
"假装夹具是规范值"，而是新增一个**渠道档位** `合成夹具`，并规定它**只允许出现在
`tests/fixtures/`**（06 D17）。配套硬断言：`data/` 里一旦冒出 `合成夹具` 渠道或 `FX-` 前缀的
id，测试立刻失败（`tests/test_engine_fixtures.py`）。于是同一套引擎、同一套门控：

- 夹具数据目录 → 出逐步计算、出比值、出满足/不满足；
- 真实数据目录 → 5 个模块全部 blocked，且逐项列出缺哪条核对。

夹具里的任何数值、式体、规则都不许复制进 `data/`——这条也有测试守着（K25）。

## 3. 主题二：条文核对与三档定档（±0.001 是怎么来的）

这一节是本项目最"贵"的部分：它买到的不是功能，而是**"哪些数字可以用"这个结论本身**。

### 3.1 为什么二态不够用（06 D15）

最初的模型是 `pending / verified` 两态。跑了一轮查证后发现它把两种完全不同的状态挤成了同
一个值：「条号、主题、表号都已按渠道原文逐字定位，但表体数值没取到」和「一无所知」都显示成
`pending`，推进看板因此失去全部信息。于是升三档：

| status | 含义 | 能否进计算 | 能否展示 |
|---|---|---|---|
| `pending` | 条号都未确认 | ✘ | 只显示"待核对" |
| `located` | 条号+主题+表号已由渠道原文逐字核对，式体/表体数值未取到 | ✘（引用即 blocked） | ✔（可展示条号与主题，数值栏写"待核对"） |
| `verified` | 式体与数值亦与正式文本核对一致 | ✔ | ✔ |

门控一点没放松（`located` 和 `pending` 一样不进计算），只是多了一档可见进度，并把"待核对
清单"从抱怨变成了可执行的工作队列——`sdc selfcheck` 的 `[7]` 看板按"核对哪一条能解锁多少项
判定"降序排列。

### 3.2 题设本身就是错的（06 D14）

题目材料写"4.4.1～4.4.6 共 8 条强条"。三个渠道交叉核对后的结论是：强制性条文为 **4.3.2、
4.4.1、4.4.3、4.4.4、4.4.5、4.4.6、18.3.3 共 7 条**，4.4.2（建筑结构用钢板）存在但**非强条**。
强条联动提示与检查单都以 7 条为准，并回写了全部计划文档。

### 3.3 "双镜像一致"是怎么被证伪的（06 D20）

原推荐口径是"两个镜像站表体逐格一致即升 verified"。M3 把这两批表体图片解码后做像素级比对：
**maxdiff = 0**——两个站点的图片是同一批底图。于是"双镜像一致"在证据学上只等于**一次读图**，
不构成两路独立。渠道白名单因此删掉"镜像双源"，新增「双主机文字层」（文字层跨主机命中才算，
图片镜像不算）。

同轮还查坏了第二个前提：φ 表与 D.0.5 拟合公式按官方生成常数
`k = (1/π)·√(235/206000)` 只有 **793 / 953** 格同点同值（早期记的"952/953"需要把常数微调
到 0.0107563 才勉强到 948/953）——交叉核对**未闭合**。

### 3.4 第三路与 ±0.001（06 D22）

用户重拍为"先补第三路独立证据再定档"。第三路是**出版社电子版 PDF 的矢量文字层**（不是扫描图
OCR），与图片逐格转录比对：

- 952 格（矢量层）× 953 格（图片转录），可比对 951 格中仅 1 格不同——a 类 λ/εk=15 那一格，
  按 PDF + 原书 OCR + 放大重读三处一致裁定为 **0.989**（另一路给的 0.990 是隐藏/串版内容）；
- D.0.5 式体三源一致（PDF 矢量还原 + 2003 版附录 C 公式图 + 计算表中间量旁证）；
- 按该式体反算全表：**953 / 953 格偏差 ≤ 0.00086**（中位 0.00026）。

于是容差口径拍板为 **±0.001**，附录 D 一套升 verified（条款 D.0.1~D.0.5、φ 表 953 格、
α₁~α₃ 六行、符号 `phi`）。为什么不能用"3 位小数取整一致"？因为那只有 **792 / 953**——
表体生成时 λₙ 的标度比官方 k 大了约 0.05%，是系统性的单向偏移而不是逐格舍入差。

### 3.5 三样东西被明确**不入库**

定档的同时登记了三条"知道但不用"：

1. **官方生成常数没取到**（V3b 永久留痕）：拟合值 `k≈0.0107563` 禁止当规范事实入库（D11/K14）；
2. **只在 PDF 矢量层出现、页面渲染图上被底线压住的那一格**（a 类 λ/εk=250=0.130）属单源隐藏
   内容，不入库；
3. **`F-D.0.5-1` 的记录保持 pending**（06 D23）：现行 AST 白名单没有条件分支，而 D.0.5 是
   分段式（λn≤0.215 与否则式），两支都指派生目标 `phi`。若把它升 verified，依赖一闭合引擎
   就会在求解阶段抛错——等于给轴压模块埋雷。式体文字进 `notes`，等引擎支持"分段/按条件选式"
   之后再升。M5 没有做这个引擎改动，所以**轴压模块目前永远 blocked**，这是如实的已知缺口。

### 3.6 定档的净效果

verified 从 0 变成"条款 5 / 表 2 / 符号 1"，但强度设计值 f 仍来自 located 的表 4.4.1，
φ 曲线的分段式仍未定档 ⇒ **没有任何一个模块开始出数值**。剩下同一批底图的表
（4.4.1 / 4.4.5 / 4.4.6 / 11.4.2-1 / 11.4.2-2 / 7.4.6 / 7.4.7 / 7.2.1-1-2）按分级口径保持
located、`values: []`。

## 4. 主题三：合成语料与内置基准

### 4.1 确定性生成纪律

没有标注数据是这类项目的死结。解法是程序化自制：**生成器同时产出输入文档和真值**，固定 seed
可复现，还能注入已知缺陷做配对评测。为了让它真的可复现，落盘路径上禁了三样东西
（06 与 plan/05 §五）：

- 禁 stdlib `random`（不承诺跨版本序列一致）→ 自研 splitmix64；
- 禁 set 迭代序 → 全部 `sorted` 落盘；
- 禁系统时钟 → docx 的 `docProps` 里 creator/lastModifiedBy 写占位符、时间戳写死 epoch、
  zip 成员用 `ZIP_STORED` 与固定 `ZipInfo`（deflate 输出随 zlib 版本而变）。

产物 `data/synth/` 整体作为**字节冻结 fixtures 入仓**，禁止手改：`sdc synth --check` 与
`tests/test_real_data.py` 会当场抓住。改体例或改生成器 → 用固定 seed 重新生成整目录提交。

### 4.2 语料形态与真值语义

24 份合成设计说明 = 12 份干净 + 12 份含注入（3 类注入各 4 份：焊缝质量等级缺标注、钢材牌号
前后矛盾、主受力连接螺栓性能等级不匹配）。plan/05 §五 原列 5 类注入，M3 落地 3 类——那 2 类
（抗滑移系数缺失、防火/防腐与用途冲突）需要跨参数推理，判定依据又都还没核对完，先不做。

真值语义一次定清（这是评测含金量的关键）：注入项记**主期望**（primary），同一注入隐含的其余
结论记 `also_expect`，评测按"该文档全部非 pass 集合"对账。否则一次"牌号前后矛盾"的注入会
因为连带触发的第二、第三条判定被算成误报——误报 0 的硬门就变成了自设自破。

### 4.3 四基准与四态指标表

`sdc bench --all` 一条命令跑四个基准并输出一张指标表：**算例通过率 / 确定性回归 /
解析 F1 / 缺陷检出率与误报**，外加条款可溯源率、待核对闸门、0 外链三条硬断言行。

指标状态四值（口径 K43）：**达标 / 未达标 / 不可判 / 不可用**，退出码 0 / 1 / 2。
关键设计是后两个状态**不许合并**：

- 分母 0 记「不可判」并显式写"分母 0，样本待补"，不记通过；
- 通路拿不到（比如冻结 exe 找不到 CLI 子进程）记「不可用」并原样说明，不记达标。

README 那张表就是 `sdc bench --all --markdown` 的输出，`tests/test_suite.py` 里有一条
`test_readme_metrics_table_matches_a_live_run` 逐行与实跑对账——改了数据没重跑 README，测试
就是红的。两个「不可判」至今没解除：`data/cases/` 仍 0 例（真值要书名+版次+例题号齐全），
10 条核查规则的依据条款全部只 located ⇒ 可硬判 abnormal 的规则分母 0 条。

### 4.4 解析与判定分进程（口径怎么一步步收紧）

阶段 0 的设想是"判定层不 import `re`"。M4 实测发现这句字面表述**不成立**：
`bench` / `rules.engine` / `selfcheck` 在 import 阶段就复用了 `parse.slots` 的 9 条抽取式
（为了共用取值归一函数）。成立的部分是"判定层不读文档、不对文档执行抽取式匹配"，于是口径
被更正为**解析与判定分进程**（K26 更正，06 D24①）。

收紧分三步：

1. **K39**：一键基准的解析步骤走子进程 `sys.executable -X utf8 -m sdc parse`，套件进程不
   定义、不编译、不执行项目正则；
2. **K45**：打包态（PyInstaller 冻结）拿不到 `-m sdc`，通路改为同目录/邻接的 `sdc-cli.exe`，
   显式指定走 `SDC_CLI_EXE`；两条都不成立返回 None，调用方把对应指标记「不可用」；
3. **K48**：桌面界面页签②的文档解析也走这条子进程通路 ⇒ **界面进程始终不执行项目正则**。

这条通路真正的存在理由是本机环境事实：Python 3.8 的 `sre_parse` 是已知的随机崩溃点，让一次
正则崩溃打挂整套评测是不可接受的。

## 5. 交付形态

- **命令面**：`sdc selfcheck / synth / run / bench / parse / check / checklist / report / gui`；
  退出码语义（0 完成 / 1 降级完成 / 2 输入不可用）定稿后锁进 CLI 测试。
- **桌面界面**：PySide6 五页签（验算台 / 设计说明核查 / 规范检查单 / 报告导出 / 知识库与状态）。
  界面没有第二套判定：正文面板就是命令面渲染器的输出，`tests/test_gui_contract.py` 把 GUI 与
  `cli.main` 现跑的输出**逐字对账**（含 `bench --all` 整张指标表与三类 docx 的字节相同）。
  页面通知走可注入通道，界面源码里出现 `QMessageBox` 即测试失败（模态框会挂死 offscreen 测试批）。
- **打包**：onedir 双 exe（`sdc-cli` 不含 Qt、`sdc-gui` 含）。白名单单源在 `scripts/bundle_rules.py`，
  spec 与构建后断言读同一份名单；构建红线四组断言（禁区成分 / 内嵌数据含子目录逐份 sha256 对账
  且不许多出文件 / PySide6 只在 GUI 包 / GUI 旁边找得到 CLI exe），任一违反 exit 1。
  版权红线数据（含渠道 URL 的台账、0 例的算例目录）明确不入包。
- **干净环境验证**：把两个包复制到仓库树**之外**的中立目录，剥掉 PATH 里的所有 Python 再跑
  CLI 六连 + GUI 存活探针。必须在树外跑，因为 `find_data_dir` 的 CWD 上溯会命中仓库 `data/`，
  那样"内嵌数据"就验了个寂寞。

## 6. 已知限制（诚实清单）

1. **没有任何模块在真实数据上出数值**。轴压模块还额外卡在 D.0.5 分段式未支持（§3.5）。
2. **算例通过率与 abnormal 分母两个「不可判」**——要真的教材/手册例题（书名+版次+例题号齐全）
   才能解除，不许为了绿灯编来源。
3. **PDF 输入未支持**，设计说明只吃 `.docx/.txt/.md`。
4. **docx 交付物只有段落**，没有 Word 表格/标题样式（M4 留的版式 spike 没跑）。
5. **解析侧有已知缺口**：`spacing` / `edge` / `end_distance` 与螺栓数量类槽位未支持，
   `sdc selfcheck` 会把相关规则报成 `slot_unsupported`。
6. **条款库只登记"标准号 + 条号 + 要点转述 + 出处"**，不整条转载规范正文；导出物不写渠道 URL、
   不写绝对路径（0 外链断言连带把机器用户名与 home 路径一并拦下）。

## 7. 复现

```bash
py -3.8 -X utf8 -m sdc bench --all        # 一键四基准 + 指标表（退出码 1 = 有不可判项）
py -3.8 -X utf8 -m pytest -q -rs          # 全套测试（GUI 两个模块需 .[gui]）
py -3.8 -m PyInstaller --noconfirm sdc.spec
py -3.8 -X utf8 scripts/verify_dist.py    # DIST_AUDIT_OK
py -3.8 -X utf8 scripts/clean_env_check.py  # CLEAN_ENV_OK
py -3.8 -X utf8 scripts/audit_release.py all  # 脱敏与产物本体扫描：DESENSITIZE_AUDIT_OK
```
