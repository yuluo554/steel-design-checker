# 05 数据计划与里程碑

## 一、数据先行总则（阶段 1 纪律）

四类数据资产，每份在 `data/README.md` 登记**来源 + 许可 + status**：

| 目录 | 内容 | 真值性质 | 规模目标 |
|---|---|---|---|
| `data/clauses/` | 条款库（GB 50017-2017 连接与轴压章节 + GB 55006-2021 条目） | 出处（标准号+条号+渠道），非数值真值 | 首期 60～120 条 |
| `data/tables/` | 数值表（强度设计值、预拉力 P、抗滑移系数 μ、稳定系数 φ、长细比限值、构造限值） | 原文表格值 | 8～12 张 |
| `data/cases/` | 教材/手册算例真值库（输入 + 期望中间量 + 期望比值 + 来源） | **数值真值**（基准核心） | 首期 ≥ 25 例（5 模块各 ≥ 5） |
| `data/synth/` | 合成设计说明 docx + 参数卡真值 JSON + 注入缺陷清单（配对） | 程序化自制带真值 | 首期 ≥ 40 份（干净/缺陷 1:1） |

## 二、条款库骨架（M1 交付物）

> ⚠️ 下例中的 `GB50017-2017:7.6.3`、章节名与 `F-7.6.3-1` 均为**格式示例**（占位），实际条号待 M1 原文核对后回填；`status` 一律以 `pending` 起步。

```json
{
  "id": "GB50017-2017:7.6.3",
  "standard": "GB 50017-2017",
  "standard_title": "钢结构设计标准",
  "chapter": "7 连接计算 · 7.6 角焊缝连接",
  "clause_no": "7.6.3",
  "title": "角焊缝强度计算",
  "kind": "formula | table | limit | construct | mandatory",
  "mandatory": false,
  "status": "pending | verified",
  "verified_by": { "channel": "官方/建标库/纸质规范", "url": "", "date": "YYYY-MM-DD", "note": "核对方式" },
  "gist": "要点化表述（不整条转载正文，规避版权）",
  "formulas": ["F-7.6.3-1", "F-7.6.3-2"],
  "symbols": ["h_e", "l_w", "beta_f", "f_f_w"],
  "tables": ["T-4.4.x-weld-design-value"],
  "limits": [{ "param": "min_h_f", "op": ">=", "value": 1.5, "unit": "mm", "basis": "构造条号" }],
  "supersedes": "GB 50017-2003:7.2.2（如适用，标注体系差异）",
  "notes": "与 2003 版差异 / 适用前提 / 已知争议"
}
```

**status 生命周期**：新建一律 `pending` → 逐条核对原文（记录渠道+日期+URL）→ `verified`。`verified` 的数值/表值才能进计算路径（引擎门控，见 03 §三.2）。
**强制条文**：`mandatory: true` 的条目（4.3.2、4.4.1～4.4.6、18.3.3）在任何计算路径命中时注入核对提示。
**待核对清单**：`scripts/selfcheck` 输出 pending 列表（按模块聚合），作为 M1/M2 的推进看板。

## 三、数值表清单（M1，逐表挂出处）

| 表 ID | 内容 | 维度 | 归属模块 | 核对状态 |
|---|---|---|---|---|
| T-steel-design-value | 钢材强度设计值 f / f_v / f_c | 牌号 × 厚度（或直径）分组 | 全部 | ⬜ |
| T-weld-design-value | 对接焊缝抗拉/抗压/抗剪强度设计值 | 质量等级（一/二/三）× 受力方向 × 是否焊槽 | A1/A2 | ⬜ |
| T-fillet-weld-value | 角焊缝强度设计值 f_f^w | 牌号（× 手工/自动焊） | A2 | ⬜ |
| T-bolt-design-value | 普通螺栓抗拉/抗剪/承压强度设计值 | 性能等级（4.6/4.8/5.6/8.8）× 受力类型 | A3 | ⬜ |
| T-hbolt-preload | 高强螺栓预拉力 P | 性能等级（10.9/8.8）× 公称直径 | A4 | ⬜ |
| T-slip-factor | 抗滑移系数 μ | 连接件表面处理（喷砂/红锈/赤砂/富锌漆等）× 钢种 | A4 | ⬜ |
| T-buckling-curve | 轴压稳定系数 φ（a/b/c/d 类） | 截面分类 × 正则化长细比/λ | A5 | ⬜ |
| T-slenderness-limit | 容许长细比 [λ] | 构件类型（受压/受拉/支撑等） | A5 | ⬜ |
| T-construct-limit | 构造限值（最小/最大焊脚、l_w 与 h_f 倍数、螺栓最小间距与边距） | 参数 × 条件 | A1～A4 | ⬜ |

**交叉核对规则**：φ 表与 φ 拟合公式（若两源皆有）必须同点同值（容差内）才升 `verified`；只有单源则入库并在 `notes` 写明"单源，未见交叉印证"。

## 四、教材算例真值库（M1～M2，基准含金量核心）

```json
{
  "case_id": "CASE-A2-FILLET-003",
  "module": "fillet_weld",
  "source": {
    "type": "textbook | handbook",
    "title": "钢结构连接节点设计手册（第4版）",
    "isbn": "", "edition": "", "page": "", "example_no": "例 3-2-11",
    "quote_note": "例题编号与数值逐字录入，禁止凭记忆推算"
  },
  "inputs": { "grade": "Q355B", "h_f": 8, "l_w": 240, "n_welds": 2, "N": 420, "unit_force": "kN" },
  "applicability_checks": ["质量等级", "受力方向（正面/侧面）"],
  "expected": {
    "intermediate": [{ "symbol": "h_e", "value": 5.6, "unit": "mm" }],
    "stress": [{ "symbol": "tau_f", "value": 15.6, "unit": "MPa" }],
    "ratio": 0.83,
    "conclusion": "satisfied"
  },
  "tolerance": { "rel": 0.02, "abs": 0.05 },
  "status": "pending | verified",
  "notes": "单位换算与四舍五入口径写在这里"
}
```

> ⚠️ 下例 JSON 的 `case_id`、书名、例题号与数值均为**结构示例（占位）**，不入台账、不作为真值；真实登记必须逐条来自可查证出处（D07）。

**纪律**：
- 无来源（书名+版次+例题号/页码）的数值**不得作为真值**；此类降级为 `data/selfcheck/` 下的**引擎自校验样例**（只做单位一致性、单调性、极限情形断言），不参与通过率统计；
- 通过率 = 引擎输出与 `expected` 在容差内的比例，目标 **100%**；容差判定口径（相对/绝对/谁主导）写进生成器与比对脚本注释，一次定清（真值语义）；
- 已知坑：手工四舍五入造成的教材值尾差、同一教材用旧版规范（GB 50017-2003）算例（体系不同，须标注或剔除）、单位 kN↔N、mm²↔cm² 混用。

## 五、合成设计说明生成器（M1 骨架，M3 完整）

**目的**：解决"没有标注数据"的死结，让文本核查评测零成本重复且可配对。

- 体例库：设计总说明段落模板（材料、焊接、螺栓、涂装防火、构造要求 5 段），同义表述 3～5 变体（"采用Q355B钢"/"钢材牌号Q355B，质量等级B级"…），固定 seed 组合；
- 槽位真值：每份生成同时输出 `params_groundtruth.json`（牌号/质量等级/焊缝等级/螺栓等级/防火时限/涂装体系…+ 段落定位）；
- 缺陷注入类型（首期 5 类，逐类可配开关与计数）：
  1. 焊缝质量等级缺标注（一/二级要求未写明检验等级）；
  2. 螺栓性能等级与构件/受力不匹配（如主受力连接用 4.6 级）；
  3. 钢材牌号前后矛盾（第 2 段 Q355B、第 5 段 Q235B）；
  4. 抗滑移系数/摩擦面处理要求缺失（高强螺栓摩擦型前提）；
  5. 防火/防腐要求与构件用途冲突（或限值越界）；
- 真值语义：注入项记主期望（primary），同一注入隐含的其余结论记 `also_expect`，评测按"文档全部非 pass 集合"对账（避免把连带结论算成误报）；
- 互斥坑（当场登记）：同一参数被两处注入相互打架、多值时判定封顶、旧行未清除导致重复检出；
- 确定性：自研 RNG（splitmix64，禁 stdlib `random`）、`sorted` 落盘、docx 无时间戳元数据（`docProps/core.xml` 的 creator/lastModifiedBy 一律占位符）、两次生成逐字节一致（守门测试）；
- 产物：`data/synth/` 整体作为**字节冻结 fixtures 入仓**，禁止手改；改模板 → 固定 seed 重新生成整目录提交。

## 六、评测指标与门槛（M4 定稿，写入 README）

| 指标 | 定义 | 门槛 | 脚本 |
|---|---|---|---|
| 算例通过率 | 容差内算例数 / 已核对真值算例总数 | **100%**（pending 算例分列不计入分母） | `sdc bench --cases` |
| 确定性回归 | 同输入两次运行结果一致 + 产物字节一致 | 100%，违反即 exit 1 | `sdc bench --sweep` |
| 解析 F1 | 字段级 P/R/F1（参数卡真值 vs 解析结果） | ≥ 0.95 | `sdc bench --parse` |
| 缺陷检出率 | 检出的注入缺陷 / 注入总数（按类型分列） | ≥ 0.95，目标 1.0 | `sdc bench --audit` |
| 误报 | 非注入项被判为异常 | **0**（硬门） | 同上 |
| 条款可溯源率 | 结论/规则带 `clause_id` 的比例 | 100% | `sdc selfcheck` |
| 待核对闸门 | 引用 pending 数据仍能出数值结论 | 0 例（必须 blocked） | `sdc selfcheck` |
| 0 外链 | docx/产物无外部引用 | 硬断言 | 报告测试 |

## 七、里程碑（M1～M6，每阶段有可演示物）

| 里程碑 | 内容 | 可演示物 | DoD（简化，细目见 HANDOFF） |
|---|---|---|---|
| **M1 数据先行** | 条款库骨架 + 数值表入库（status 纪律跑通）+ 算例真值库第一批 + 合成生成器 v0 + 台账 | `sdc selfcheck` 输出 pending 看板；数据 schema 校验测试全绿 | 每份数据挂来源；条款库 ≥60 条且 status 字段完整；算例 ≥15 例（含来源）；生成器两次运行字节一致 |
| **M2 公式引擎** | 5 个验算模块 + 符号求值与查表 + status 门控 + 强条联动提示 | `sdc run` 出逐步计算 + 依据条款；`sdc bench --cases` 通过率 | 已核对算例 100% 通过；引用 pending 数据必 blocked；失败路径测试齐（缺字段/非法枚举/单位越界） |
| **M3 文本核查** | docx/PDF 抽取 → 参数卡 IR → 规则引擎三级判定 + GB 55006 检查单 | `sdc check --doc` 出异常清单；`sdc checklist` 出符合性清单 | 解析 F1 ≥0.95；误报 0；每条 finding 挂条款与原文位置 |

| **M5 桌面交付** | PySide6 5 页签 GUI + CLI 契约 + PyInstaller onedir 双 exe + 打包断言 | exe 在中立目录双击可跑；GIF/截图 | GUI 只调引擎 API（无第二套行为）；dist 树遍历断言通过；`find_data_dir` 分支测试；干净环境按 README 跑通 |
| **M6 发布收尾** | 脱敏四步 + 构建产物扫描 + 邮箱全历史改写 + GitHub 公开 + Release（exe）+ 技术报告 + 收尾固化 | Release 页 + 徽章 | 三扫全 0；CI 矩阵全绿；tag/release 经用户确认；缓议项清零 |

**顺序依赖**：M1 数据是 M2 的准入门（未核对不进计算），M2 引擎是 M4 基准的被测对象，M5 只消费 M2～M4 的 API。
